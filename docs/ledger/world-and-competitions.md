# World/leagues, promotion & playoffs, continental and domestic cups, Americas, title playoffs, super cups

> Moved verbatim from CLAUDE.md on 2026-09-25 to keep session context small. This is the detailed ledger for this area: read it before touching the code it describes, and add new entries here, not to CLAUDE.md. References to "this file" below meant CLAUDE.md as a whole; the other sections now live alongside this one in `docs/ledger/`.

**World / leagues** (competitions-as-data)
- `core/competitions.ts` — `Competition{id,country,tier,name}`, persisted `LeagueStore.competitions`. Teams carry `compId` (not a raw division number). Every "div 0 vs 1" pair is a loop over competitions. Finance fns take a `scale`, looked up via `financeScale`.
- **Per-league tuning lives ON the `Competition`, and the player can add leagues (2026-08-21).** `Competition` gained four **optional** fields — `strengthOffset`, `academyOffset`, `budgetScale`, `continentalSlots` — resolved through accessors (`competitionStrengthOffset`/`competitionAcademyOffset`/`competitionBudgetScale`/`isWeakLeague`/`academyBaseCenterOf`) that fall back to the `COUNTRY_*` tables. **Absent ≠ defaulted**: every shipped competition leaves them unset, so the default world and every existing save read exactly as before and there is **no migration**. The record was the right home precisely because `LeagueStore.competitions` is already per-save persisted state — no new settings store, nothing threaded through `src/core`. `generateWorld`/`createLeagueState` now take the table (defaulting to `worldCompetitions()`); `buildCompetitions(LeagueSpec[])`/`worldLeagueSpecs()` assemble one, and a test pins that rebuilding the shipped specs returns `worldCompetitions()` byte-for-byte (the "leave an untouched knob absent" rule is what makes that hold). UI is `ui/components/WorldSetup.tsx` on `/new-league`, **in every mode, roster import included (2026-08-28)** — see the roster-mode entry below for why it used to be hidden there and what had to change first. `worldTuningWarnings` is advisory-only and flags the weaker-but-richer inversion, plus (since names became editable) two divisions sharing one name, which would make a roster file aimed at that name fill only one of them.
  - **Division names are player-set (`LeagueSpec.d1Name`/`d2Name`, exposed 2026-08-28).** The fields already existed and `worldLeagueSpecs()` already filled them from the shipped table; what was missing was any control, so a division was always "`<country>` Division N". That is not cosmetic: `resolveRosterSlots` matched a world-wide roster file's competitions **by name only**, so a file written for "Eredivisie" could never apply to any world the game could build. Renaming is offered on shipped rows behind a per-row toggle (`renaming`, a `Set` of entry ids) and inline on added ones. `buildCompetitions` treats an all-whitespace name as absent (`?.trim() ||`), so emptying the box reverts to following the country rather than producing a blank league name.
    - **The other half of that coin was a trap, and matching now falls back to COUNTRY + TIER (2026-08-31, user ask).** A name is the one identifier the player can invalidate, and renaming was the *documented, encouraged* thing to do — so renaming England's top flight to "Premier League" silently cost you every file written for "English Division 1", which is **every file the EA FC converter has ever produced**, i.e. the Download Real Rosters file itself. The user reported it as "I want to rename the leagues and still import the real players file". `resolveRosterSlots` now tries three routes per file competition, most authoritative first: an explicit `country`/`tier` on the entry (new optional fields, parsed strictly, emitted by `buildRosterFile` and the converter), then the literal name, then **the country and tier the name DESCRIBES** (`competitionRefFromName`). A country is not renameable on a shipped league, so the third route is what carries an untouched file across any rename.
    - **`competitionRefFromName` reads names back through `worldCompetitions()`, NOT a hand-written demonym table.** Shipped names are adjectival ("Dutch Division 1" is the Netherlands'), so the mapping is real data rather than derivable from the country string — but it is data the game already ships, so building the lookup from the competition table means adding a country puts its name in for free and the two cannot drift. The second form, `"<country> Division <n>"`, is what an *added* league is called by default and is handled by regex. Anything else ("Eredivisie") returns null and matches by name alone, which is correct: nothing in that string says which country it is, and that is precisely what the new `country` field is for.
    - **Two consequences worth knowing.** (a) `RosterSlotWorld` now needs `country`/`tier` on its competitions — satisfied structurally by both `LeagueStore` and `worldTeamSlots`' caller, so no call site changed, but a hand-built fixture must carry them. (b) A competition can be **claimed once**: two entries reaching the same division (now possible under two different names) would both write onto the same slots with the later silently winning, so the first claim holds and the collision is warned. `retargetRosterFile` **strips** any stated country/tier, since leaving "England, tier 1" on an entry now aimed at Neverland would send it straight back to England.
  - **`academyOffset` is split from `strengthOffset` in the engine but DELIBERATELY NOT EXPOSED in the UI (user call, 2026-08-21).** `generateDivisionTeams` computed a single `base` and used it *both* to generate players and as the club's permanent `academyBase`, so "how good is this league now" and "what does it keep producing" were literally the same number. They're now separate params; the strength spread is still drawn and shuffled **once** and both bases derive from it, so rng consumption is unchanged and — since `competitionAcademyOffset` falls back to `strengthOffset` — leaving it unset reproduces the old behaviour exactly. It works: measured on `scripts/customWorldProbe.ts`, a league generated 1.87 OVR *below* its neighbour finished 1.44 *above* it after 3 seasons on academies alone, and it is safe to set because `academyBase` is fixed-at-generation by design (it's the anti-inflation anchor, so setting it picks an equilibrium rather than opening a ratchet). **The control was cut because a second 0-20 slider beside Strength made the player do arithmetic to work out which way their league was pointing** — the mechanic was fine, the affordance wasn't. If it comes back, make it a *direction* ("rising / steady / fading") and derive the offset, rather than a second absolute scale. The field, the accessor, the generation split and their tests all stay; `newLeagueEntry` simply leaves it unset.
  - **Continental slot counts are per league, which forced the Shield's offset to be derived.** `CupFormat.strongOffset`/`weakOffset` were constants duplicating the Cup's slot counts ("change one and you must change the other"). That breaks the moment a league sets its own count, so `cupOffsetForCompetition` now sums the slots of every competition above it in `CONTINENTAL_ORDER` — fields butt up exactly, can't overlap or gap, and inserting a third competition shifts everything below it automatically.
  - **`isValidCupFieldSize`/`largestValidCupField` (`constants.ts`) — a real crash this exposed.** The league-phase draw needs the field to split into 2 pots that are *each even* (intra-pot rounds are perfect matchings within a pot) and big enough for `CUP_LEAGUE_PHASE_GAMES/POTS`, plus ≥ `CUP_MIN_FIELD` (12 — held where it has always been, so which worlds get a competition at all is unchanged; the draw and `cupKnockoutPlan` would both cope with 8). `drawLeaguePhase`'s own guard **omitted the even-pot condition**, and `cupPlan` only checked the minimum — unreachable while every field was a shipped size, but a custom world producing 23 qualifiers threw inside `simOffseason`. `cupPlan` now trims to the largest buildable size and `qualifyCupTeams` slices **after seeding** (drops the world's weakest qualifiers, not an arbitrary league's). Shipped world still lands on 24/16 exactly, so nothing there changed.
  - **Per-league roster import (`retargetRosterFile`, `leagueRosterFiles`).** An added league's divisions did not exist when any roster file was authored, so nothing in a file can name them and `resolveRosterSlots` would skip every competition as unrecognised. `retargetRosterFile` rewrites a file's `match` values onto one league's division names **positionally** (first competition → tier 1), the same rule clubs already follow onto slots; `WorldEntry.rosterSources` holds the files and `leagueRosterFiles` retargets them at build time, **not** at pick time, because the division names follow the country name and the player can rename the league after loading. The result is folded through `combineRosterFiles` → `applyRosterFileToNewLeague` like any other import, so slot resolution, the picker preview and crest suppression are shared. Retargeting is non-mutating and drops (with a warning) any competition past the league's division count.
  - **The world editor is available in roster mode, and the fix that allowed it was to stop storing the resolution (2026-08-28).** It was hidden on `?roster=1` for a real reason: `NewLeague` held the loaded file **already resolved onto slots** (`useState<LoadedRoster>`), so reshaping the world underneath it left `byTid` pointing at clubs that had moved. That is the wrong half to fix by hiding a panel — **the world editor is exactly what a player needs when a file doesn't fit**, since `resolveRosterSlots` skips any competition the world hasn't got by that name, and adding or renaming a league is the only way to make such a file apply at all. The page now holds **only `NamedRosterFile[]`** and derives every resolution (`useMemo`) against the world as it currently stands, so a reshape re-aims the file instead of misaiming it. Two consequences: the two roster sources are no longer mutually exclusive, so `activeRoster` **combines** them (world-wide first, per-league last, because a league carrying its own file is the more specific claim on the competition it names — `combineRosterFiles` gives the later file the win); and a world change that alters the **slot layout** clears `selectedTid` (`changeWorld` compares the tid→compId layout before and after), because otherwise the club you picked in the list is not the club the save starts you at. A rename or a strength/money retune leaves the layout alone and keeps the selection. World-wide roster files can also be loaded from the plain `/new-league` screen now, so the two entry points differ only in which screen they open on.
  - **A league panel leads with SHAPES, not sliders (`core/worldPresets.ts`, 2026-09-21, user ask).** Opening England gave you `Strength 20`, `Money 1.00` and eighteen selects, which states every knob and answers no question a person has. Ported from God Mode's Awards tab, which the user approved as the house pattern for any tuning editor: named presets first (`LEAGUE_PRESETS`, each a real shipped arrangement so the blurb can name it and the numbers are already audited), a **What this builds** panel read off `resolveLeagueSpec` — so it describes a shipped country truthfully, most of whose knobs are absent — and every existing control moved behind a `Fine-tune this league` disclosure that opens by itself only when `matchingLeaguePreset` returns nothing. **No Save/Discard bar, unlike Awards**: this edits live pre-save config rather than a draft, so the preview is the confirmation.
    - **"As shipped" must compare against the country's OWN spec, and testing for absent knobs is the bug.** A shipped spec is **not** knob-free — `worldLeagueSpecs()` carries its sizes, divisions and promotion counts back precisely so `buildCompetitions(worldLeagueSpecs())` still equals `worldCompetitions()` — so the first cut read **every shipped country as "Custom"** and opened Fine-tune on all sixteen. `matchingLeaguePreset(spec, baseline)` and `applyLeaguePreset(spec, preset, baseline)` both take that baseline; restoring copies its values back rather than deleting keys, since clearing them hands England the generic defaults and rebuilds it as an 18-club league. Caught in a browser on the first render.
    - **The money-follow switch must NOT fire on "As shipped".** `linkMoney` writes `suggestedBudgetScale`, and England ships with no `budgetScale` at all, so restoring it would leave the country carrying a knob it never had — absent and equal-to-the-default are different claims, which is the same distinction the whole editor rests on. Only a preset that sets a strength of its own takes the follow.
    - **The strength line quotes a MEASURED rating** (`STRENGTH_ANCHORS`, from `scripts/strengthAnchorProbe.ts`, re-measured 2026-09-21 on the 884-club world: offset 0 → best club 87, 5 → 81, 10 → 79, 12 → 76, 20 → 68). They are OVR on the current scale, so **re-measure after a scale move rather than adding a constant**. `describeStrength` takes the country so it never compares one to itself ("about as strong as England" on England's own panel).
    - Pinned by `test/core/worldPresets.test.ts` (every preset round-trips back to the shipped spec; the whole restored world still equals `worldCompetitions()`; every preset survives `normalizeLeagueSpec` unchanged, so a preset can't offer a league the engine would have to correct) and `test/ui/worldSetupPresets.test.tsx` (shipped reads as shipped, the disclosure's default state, the raw controls still in the DOM behind it).
  - **The world editor CARD now collapses, and it must default open in roster mode (`WorldSetup`'s `defaultOpen`, 2026-08-30).** Twelve shipped countries is the tallest block on a page whose job is picking a club, and most saves take the world as it ships, so it is shut by default and the header carries a summary of the world it would build (`N countries, N divisions, N clubs`) — which is the whole reason collapsing is safe, since you can see what you are getting without opening it. **Two things would otherwise go silently missing.** (a) `worldTuningWarnings` renders *inside* the body, so a shut card would swallow advice the editor raised; the header counts them as a badge. (b) A roster file naming a league this world hasn't got is skipped entirely and the editor is the only cure, per the entry above — so `NewLeague` passes `defaultOpen={!!worldRoster}` and an import opens it. Collapsing it there would hide the fix behind a card the warning merely points at. Gotcha for tests: `worldSetupRender.test.tsx`'s harness passes `defaultOpen: true`, because every case in it is about what the editor *contains* and a shut card renders only its header; the shut state has its own block at the bottom of that file.
  - **The club picker shows ONE division at a time (2026-08-30).** Forty club rows for a big country buried everything under the picker, and the two divisions are alternatives rather than one list to read end to end. Tabs carry the real division names, so a renamed or added league labels its own. Three things worth knowing: a one-division country renders no tabs and the shown tier **falls back** rather than showing an empty list (same shape as `activeCountry` falling back when a country is switched off underneath the picker); switching division deliberately does **not** clear `selectedTid` the way switching *country* must, so a line reports which division the pick is in, because an invisible selection reads as no selection with Start live at the bottom; and the tier is a **view**, never save state — which division a club plays in is still read off its tid via `tierForTid`.
  - **Slider anchors are measured, not extrapolated (`scripts/strengthAnchorProbe.ts`).** Generates every strength rung 0-20 in one world so they're directly comparable, and reports division mean OVR, best/worst club rating and best player per rung. Confirms ~0.94 OVR per point and gives the cross-league anchors the Manual and the settings guide quote (e.g. strength 9 → best club ≈ 67, about a mid-table big-four side; strength 20 → best club 54, below *every* big-four club).
  - **Division count (1 to 3) and size (even, `MIN_DIVISION_TEAMS` 8 to `MAX_DIVISION_TEAMS` 20) are per league (2026-08-22, deepened 2026-08-30).** `Competition.teamCount` + `competitionTeamCount`; `LeagueSpec.divisions`/`d1Teams`/`d2Teams`/`d3Teams`. A country's divisions are a **chain**, not a pair — see the N-deep pyramid entry under Promotion/relegation. `worldTeamSlots`/`countryClubRanges` **no longer take team counts** (they derive them per competition), which is why the club-identity lookup had to be country-anchored first: a country with a different number of divisions shifts every later country's tids by a whole division.
    - **A smaller division SPREADS across the fixed 38-matchday grid rather than finishing early** (`spreadOverSeason` in `leagueState.ts`): round r of R maps to `round(r * SEASON_MATCHDAYS / R)`. At R=38 that is the identity, so **the shipped world is untouched** (pinned by the `touchStats` hash and a test asserting matchdays 1..38 exactly). Spreading is what keeps the rest of the calendar meaningful for a short season — the winter window still opens mid-season, deadline day still has games left, the run-in still lines up with the continental finals. `MAX_DIVISION_TEAMS` is 20 because 2(n-1) ≤ 38 and `matchdayToMonth` **throws** outside the grid; going past it means moving the cup matchday tables too.
    - **Blank matchdays broke the injury/ban tick, exactly as CLAUDE.md warned they would.** Both count in MATCHES and both decremented once per matchday for *everyone*, which is exact only while every club plays every matchday. `applyInjuries`/`applySuspensions` now take a `played(pid)` predicate; `simThrough` builds it as **"who did NOT play"** so free agents (on no roster, no fixtures to attach to) keep ticking on the global clock as before, and the shipped world's set is empty. Both default to "everyone played", so no other caller changed.
    - `updateHype` takes the club's own division size — finishing 8th of 8 has to score like bottom, not like 8th of 20. Defaults to `NUM_TEAMS`.
  - **Club identities are anchored to a country, never to a tid.** `CLUBS` is indexed by tid, so switching a country off (or adding one ahead of another) shifts every later country's tids and a tid lookup hands Spain's clubs England's names. `clubIdentitiesFor(country, count)` (shipped block, else `generateClubIdentities` from `teams/clubNames.ts`) is shared by `assignIdentities` **and** the new-league picker — they must derive names the same way or the save renames every club on open. The generator is deterministic from `(country, count)` on its **own** seeded stream, which is what lets the picker preview an added league before a world exists.
- `worldCompetitions()` = **48 competitions / 884 clubs** (36 / 626 until the Americas were appended on 2026-09-12 — see the Americas entry below; 852 until Argentina's and the US's top flights went to their real 30 on 2026-09-13, then 872 until their second divisions were split as well, then 898 until the real league sizes of 2026-09-18 brought it to 884, and 883 since the US second division went even on 2026-09-22 — see "Real league formats" below): England, Spain, Italy, Germany (equal siblings) + **France, Netherlands, Portugal, Belgium, Turkey, Greece, Scotland & Serbia (deliberately weaker + poorer)** + **Brazil, Argentina, Mexico & the United States**, **three divisions each, every country** via `COUNTRY_STRENGTH_OFFSET`/`COUNTRY_BUDGET_SCALE` (`constants.ts`). **The table's order is generation order, not the ladder** — appending a COUNTRY is what keeps existing countries' players byte-identical (verified: adding four countries left all eight prior leagues' generated OVR identical), so the Netherlands is appended after Turkey while sitting above Portugal on the ladder. **Adding a DIVISION is not the same thing** and does shift tids: see the third-division entry below.
  - **Division sizes are the REAL ones, not a uniform 20 (2026-08-28).** England/Spain/Italy 20, Germany/France/Portugal/Turkey/Netherlands 18, Belgium/Serbia 16, Greece 14, Scotland 12, with second tiers to match (down to Scotland's 10) — set per competition via `Competition.teamCount`, so the world is **626 clubs / 15,650 players / 10,538 fixtures** (420 / 10,500 / 7,092 before third divisions). Four things worth knowing. **(a) `MAX_DIVISION_TEAMS` is 20 and that is a calendar fact, not a preference**: a double round robin of n clubs needs 2(n-1) matchdays against a fixed 38-matchday grid, which is why England's real 24-club second tier is 20 here. Sizes must also be **even** (the circle-method fixture generator leaves an odd field unpaired). **(b) A smaller division SPREADS across the same grid** rather than finishing early (`spreadOverSeason`), so the winter window, both continental competitions and the run-in still line up — and the blank matchdays that creates are exactly why `applyInjuries`/`applySuspensions` take a `played(pid)` predicate. **(c) `worldLeagueSpecs()` is DERIVED from `worldCompetitions()` and must carry `d1Teams`/`d2Teams`/`d3Teams`/`divisions`/`promotionSpots` back**, or `buildCompetitions(worldLeagueSpecs())` stops reproducing the shipped table, which a test pins. Fields equal to the default stay absent, which is what makes that round trip exact. **(d) `CLUBS` must be trimmed to match**, because `SHIPPED_RANGES = countryClubRanges(worldCompetitions())` slices that array by the derived ranges — leaving the surplus entries in place would hand every country after the first shrunken one its predecessor's tail. Each country's block is its divisions' slots in tier order, so a shrink drops the tail of *each division*, not the tail of the block.
  - **EVERY country runs THREE divisions (2026-08-30), and the symmetry is the load-bearing part.** Sizes: the big four 20 in all three (`NUM_TEAMS_D3` by omission — the real size of a German 3. Liga even though the two above it hold 18, and the calendar cap for the other three); France/Portugal/Turkey/Netherlands 18, Belgium/Serbia 16, Greece 12, Scotland 10. Everything mechanical falls out of the N-deep pyramid work (see Promotion/relegation); what is specific to *this* world change is below.
    - **Giving a third tier to only SOME countries makes those countries stronger, and it broke the ladder.** It shipped that way first (big four only) and the 20-season 4-seed audit caught it. Measured against a control that varies ONLY the world (same N-deep code, 420 clubs): **BIG4 D1 at s21 57.8 → 60.3, BIG4→France +2.74 → +7.35, BIG4→Serbia +7.06 → +11.60**, against a documented design target of **~+3.4** for BIG4→France. Generation is identical on both (BIG4 64.5) — the gap opens over the dynasty. A three-division country has 50% more clubs producing and developing players and `enforceDivisionCeilings` pumps the best of them upward, so it drains 60 clubs where a two-tier one drains 40; and having more talent at home it buys less from the weak leagues, whose economies run on those receipts. **Symmetry removes the cause rather than compensating for it: with every country three deep, BIG4→France comes back to ~+3.4 on all four seeds.** The general lesson is that *world composition is a strength lever* — adding clubs to a country is not a neutral depth change.
    - **Solvency is a genuine, accepted cost, and three hypotheses about it were wrong before the right one.** Deficit rate went **0/42 sampled points on the 420-club control → 4-6/42 on the 626-club world, worst 2 of 625 clubs (0.32%) at once**, in the TOP FLIGHTS of the poorest countries, seasons 15-21. Ruled out by measurement, in order: **(a) tier-3 poverty** — the broke club is tier 1, not tier 3; **(b) re-roll noise** — the control is cleanly 0/42 on both seeds, not a coin flip; **(c) a size-dependent estimator** — the *rate* rose too, not just the min. What it actually is: the pre-existing weak-league wage ratchet, modestly amplified. `scripts/sweepCostProbe.ts` measures it — over 15 seasons the poorest top flights' wage-bill-to-base-income ratio runs **0.183 → 0.496 on the control and 0.189 → 0.587 with third divisions (+18%)**, with **+24% more forced upward moves** (520 → 645 cumulative). So the ceiling sweep does contribute (it is a FORCED buy: the fee is capped at what the club can pay, the arriving player's WAGES are not), but the ratchet is overwhelmingly pre-existing and nearly triples on its own. **Accepted (user call): 1-2 clubs of 626 in the red late in a long save, on a mechanism that predates this.** Fixing it properly means attacking the wage ratchet itself, which is its own project.
    - **`financeScale` COMPOUNDS country scale × tier scale, and that is a real latent problem even though it is not what caused the deficits above.** Wages are country-independent while income is scaled twice, so six leagues now sit below anything the wage curve was ever validated against: **Serbian D3 0.126 / Scottish D3 0.133 / Greek D3 0.140 / Turkish D3 0.144 / Belgian D3 0.162 / Portuguese D3 0.180, against a previously-tuned floor of 0.210 (Serbian D2) — the poorest is 1.67x poorer than anything tuned.** A floor on the combined scale is the obvious fix and it is untaken; the deficits are in tier 1, so it would not have fixed them.
    - **Ids are renumbered INLINE, not appended, and that is forced by two things.** `CompetitionSelect` groups by country and filters the table in **array order**, so a division listed out of place shows out of order in every competition dropdown in the game; and `buildCompetitions(worldLeagueSpecs())` hands out ids sequentially, so an out-of-place id breaks the round-trip test outright. England still holds ids 0 and 1. A test pins that each country's block is contiguous and in tier order.
    - **`CLUBS` grew by 206, INSERTED into each country block rather than appended.** `SHIPPED_RANGES = countryClubRanges(worldCompetitions())` slices that array by derived ranges, so appending would hand Spain England's names. Two collision classes, both measured rather than assumed: **14 of the big four's first 80 abbreviations collided** with the shipped set, and the weak countries' first pass **reused ~60 towns** their existing clubs already hold, because the smaller countries had already spent their obvious ones. Check the TOWN, not just the full name, and resolve abbreviations against the taken set programmatically.
    - **The domestic cup is now at its ceiling.** The largest field is **60** (England/Spain/Italy) needing **6** rounds against `DOMESTIC_CUP_MATCHDAYS`' **6** slots. A country past 64 clubs overflows it, and `buildDomesticCup` answers that by returning **null** — no cup at all for that country, silently. Check this before deepening any pyramid further.
    - **Perf was measured, not assumed** (`scripts/marketTiming.ts`, season 2, best of 5, same probe on both tables): **420 clubs 1745ms / 866 deals → 500 clubs 2281ms / 983 deals**, i.e. 1.19x the clubs for 1.31x the time — an exponent near **1.5**, not the ~5 the old 240→320 figure in this file implies. **Re-measure rather than extrapolating from either figure.**
    - **Two UI sites assumed exactly two tiers and one of them was silently wrong**: Frivolities rendered `tier === 2 ? "D2" : "D1"`, labelling a third-tier season **"D1"**; `DivisionBadge` collapsed everything below the top flight into one colour. Both read the tier now. Grep for `tier === 2` before adding a fourth.
    - **A third tier lands on a band the game already ships.** Rostered OVR min/p10/mean/max on a fresh world: English **D1 50/57/64.5/81**, **D2 36/42/50.5/67**, **D3 21/28/36.2/52** — and Serbian **D2 is 21/27/35.5/51**, i.e. an English third division is almost exactly the existing bottom of the world. The accepted cost is the academies: tier-3 `youthGenerationBase` is **1.00-1.50**, fully saturated on the softplus floor, so every third-tier club produces near-identical youth. A third-division save is a transfer-market game, not an academy game.
    - **D2/D3 converging is ACCEPTED (user call), and the audit encodes that.** At 30 seasons D3's strongest team reached 52.1 against D2's average 51.0, from a correct 45.4 vs 50.5 at generation — deeper tiers erode faster for the same reason the bottom of the COUNTRY ladder does (`growthDamping` throttles growth above an absolute ovr, so a tier further below it grows undamped). `divisionAudit` therefore fails only at the **D1/D2** boundary and gates deeper ones on **mean ordering** instead, which still has real headroom (D1 56.5 / D2 50.9 / D3 44.1). Note `divisionRefusalOvr(3)` = 62 barely bites anyway, since D3's best player is 61.
  - **Real division sizes exposed a pre-existing bug that uniform 20-club divisions had hidden: the free-agency queue was ordered by RAW POINTS across the whole world (`freeAgencySigningOrder`, 2026-08-29).** The offseason's step 4 is "worst club picks first" over one world-wide queue, and it sorted by `points`. A 12-club league plays 22 games, a 20-club one 38, so at equal quality the small league's clubs carried ~58% of the points and sat at the front of the queue whatever they were worth — and the pool drains by quality, so picking first is the entire prize. **Symptom:** on the coefficient audit, Scotland (12 clubs, generated second-weakest in the world) finished 20 seasons with the **highest tier-1 mean OVR of any country**, above Germany, taking Cup places off England, on both seeds. **The first hypothesis was wrong and is worth recording:** prize money (`successPayout`'s fixed rank cutoffs paid a 10-club division's *every* club top-10 money). That was real and was fixed, but moved the symptom **not at all** — 59.3/60.9 → 59.2/59.3 — because money was never the channel. **What found it was a controlled probe, `scripts/divisionSizeProbe.ts`:** six countries identical in strength, budget, promotion and nationality, differing only in club count, in twin pairs so every reading has a check. Whole-roster drift over 15 seasons ran **−1.2 / −5.3 / −8.6** at 12 / 16 / 20 clubs, monotonic, twins agreeing to within a point — and attributing it (OVR moves only in progression, so a league's *retained* players' mean change is pure progression and the remainder is churn) put **all** of it in churn, with progression running the *other* way. Churn was free agency: the same ~4.4 arrivals per club everywhere, averaging **39 OVR at 12 clubs against 26 at 20**, tracking the raw-points sort key exactly. That gap is also where the sub-40 squad filler came from (5 per club at 12 against 10 at 20) — big leagues signing junk into their holes, not small leagues developing talent. **Fix is points per game.** Within one division every club has played the same games, so ppg order *is* raw-points order and **a uniform-size world is byte-identical**; only mixed-size worlds move. **Continental Cup** (`core/cup/`) — **Swiss league phase + knockout** (all new cups)
- **32-club field** (20 → 24 with Belgium/Turkey, → 28, → 32 as four more countries joined), qualified by league position (not OVR): strong (big-four) leagues send top 4, every handicapped league sends top 2 (`CUP_STRONG/WEAK_LEAGUE_SLOTS`), so 4×4 + 8×2. **The Continental Shield is `countries × 2` = 24** and grows with every country, which is the second reason the country count must stay even. **The field size is derived, not read** — `CUP_LEAGUE_PHASE_SIZE` only documents and anchors tests; the draw and the split both work off the actual field length. A valid field is a **multiple of 4** — even, and split into `CUP_LEAGUE_PHASE_POTS` pots that are themselves even (32 → two pots of 16 ✓), which is why weak leagues all send 2 rather than some sending 1. **Skips season 1** (no prior table → `cup===null`). Cross-cut by a **shared normalization baseline** (`simThrough`'s `cupMatchData` pools the whole field) so weak clubs read as genuinely weaker. `LeagueStore.cup`/`cupHistory`, `/cup`.
- **Qualification is an allocation pass over every competition at once, not a slice of each table (`core/cup/qualification.ts`, 2026-08-28).** There are three routes in, taken in this order: **title holder** (the Cup keeps its own winner and takes the Shield's — real since 2015), **domestic cup winner** (takes one of his country's Shield places), then **league position**. `allocateContinentalPlaces` walks `CONTINENTAL_ORDER` and places each club **exactly once, in the best competition he reaches**; `qualifyCupTeams`/`buildCupState` read their format's slice, `qualificationByTid` is what the Standings shading uses. **Why it had to stop being a table slice:** disjointness used to be *arithmetic* — the Shield started at an offset derived by summing the slots above it, so the two fields provably butted up against each other. A club entering from 9th makes the qualifying places non-contiguous and no offset describes them, so disjointness is now *structural* (the `placed` set) and `cupOffsetForCompetition` survives only as a description of the usual case, for the legend and the Manual. **Slot COUNTS are untouched, and that is load-bearing:** a route never creates a place, it displaces its own league's lowest league-position qualifier, who cascades into the next competition. Field sizes therefore cannot move — and they must not, because `isValidCupFieldSize` only accepts multiples of 4 ≥ 12, so a route that grew a field would fail the *draw*, not the qualification. **The draw's same-country constraint moved from compId to country (`drawGroupOf`)**: a second-division domestic cup winner's compId is his own division, so keying on compId would let him be drawn against his country's top flight. Same equality relation for an all-top-flight field, so **existing draws are byte-identical** — the pre-change tests pass unmodified. Two gotchas: **(a)** a tier-2 entrant is seeded at `LOWER_DIVISION_SEED_BASE + rank`, below every top-flight club, because 5th in the second division isn't 5th in the first; **(b)** a special-route club who *would have qualified on merit* is labelled `"table"`, not by his route (`onMerit`, computed before any claim) — otherwise a first-placed champion's Standings row reads "as holders", which looks like a bug. Pure, **zero rng draws of any kind**, no persisted field and no migration (routes are read off `league.domesticCups` / `league.cup` / `league.shield` in `simOffseason`, which still hold the just-decided season's cups at that point). Measured with `scripts/qualificationProbe.ts`: over 5 seasons the cup route fires for 3–6 of the 8 domestic cup winners a season (the rest had qualified anyway and the place passes back down the table), holders need the route 1–2 times a season, and second-division clubs reach the Shield in 4 of 5 seasons.
- **Cup places are earned on a rolling country coefficient, not fixed by strength class (`core/cup/coefficients.ts`, 2026-08-28).** Each season the Cup's places are handed out in coefficient order: a five-season (`COEFFICIENT_WINDOW`) record of how each country's clubs did in Europe, pooling **both** competitions as UEFA does, scored as league-phase match points + per-tie wins + per-round bonuses + a title bonus, **divided by clubs entered** (so sending four is worth nothing by itself). **Two properties carry the whole design.** **(1) ZERO-SUM:** the ladder is the multiset of slot counts the world *already had*, re-sorted onto countries by rank, so the world total is arithmetically identical whatever the coefficients say. This is a **correctness requirement, not tidiness** — `isValidCupFieldSize` only accepts certain field sizes (in practice multiples of 4), so a reallocation that changed the total would fail inside the **draw**, seasons later and nowhere near its cause. It also means a custom world keeps the shape its author chose, just handed out on merit. **(2) DERIVED, NOT STORED:** computed from the archived cups a save already keeps (scorelines survive `archiveCup`; only box scores are dropped), and a club's **country never changes** (promotion moves him between his own country's divisions), so no history lookup, **no new persisted field and no `migrate.ts` change** — an existing save gets a real coefficient off its own history the moment it loads. Passed through as a per-season `SlotOverrides` on `QualificationContext`, deliberately **not** written to `Competition.continentalSlots`: that field is *user-authored* for custom leagues and a season's reallocation would destroy it. Two guards, each earned rather than assumed: **`COEFFICIENT_MIN_SEASONS` (3)** — reallocating from the first available season put Belgium on 4 places and **Germany on 2 in season 3** off a *single* season, then reverted it; a world's first cups are the noisiest data it will ever have. And the `COEFFICIENT_MIN_CUP_SLOTS` floor (a league with no places can never earn a coefficient, so zero is a **trapdoor, not a demotion**) **stands down when the world's own ladder already puts a league below it**, because that means the league was authored out of the Cup on purpose and forcing it back in would overrule its author. **Measured, `scripts/coefficientAudit.ts`, 20 seasons × 2 seeds — note every figure in the rest of this bullet was taken on the 8-country/24-club world and is kept as the record of why the design is what it is, not as a current reading:** total held at exactly 24 every season on both, zero AI deficits (poorest club per country £8.6M–£66M), and **no ratchet** — places churn around the 4th/5th cut line (7 changes on seed 1, 2 on seed 2; Italy and Germany each dipped to 2 places and came back). **It is not cosmetic: on seed 1 France finished on 4 places and England on 2**, England's coefficient falling 11.83 → 8.10 while France's rose 6.17 → 8.42. - **League phase** (`core/cup/leaguePhase.ts`) — one combined table, each club plays `CUP_LEAGUE_PHASE_GAMES` (6) games. - **Knockout** is format-aware (`isSwissCup`/`koRoundsOf`/`koRoundMatchdays`/`koLegMatchdays`/`koPrizeByRound`/`koFinalRound`): Swiss = QF→SF→Final (3 rounds). **QF/SF are two-legged, home-and-away, decided on aggregate** (`CupState.twoLegged`, true for all newly-built cups; final and playoff always single-leg). - **Continental prize money: qualifying is the biggest single payment, not the trophy (2026-08-31, user call).** The prize tiers shipped "title-ish" — £2M for reaching the league phase against £30M for lifting the Cup — which made a six-game campaign against the best clubs in the world worth **a tenth of finishing 5th in your own division** (`PRIZE_TOP_5`, £20M), and made the whole competition a lottery ticket rather than something a club builds a season around. Real continental football is the other way up: UEFA's starting fee is roughly what *reaching the final* pays. So participation went £2M → **£10M**, the league phase now pays **per result** (`CUP_PRIZE_LP_WIN` £1.5M / `CUP_PRIZE_LP_DRAW` £500k, the draw paid to both clubs), and the knockout tiers came down to meet them (final £30M → £14M). The money moved to the *front* of the competition rather than into it, so this is a redistribution among the same clubs far more than an injection. What moved is the ratio that matters: a league-phase exit went £2M → ~£14M against `PRIZE_TOP_5`'s £20M. Quote that ratio, not the trophy, when re-tuning.
  - **The pot is dominated by the league phase, which is the easy thing to get wrong.** 32 clubs collect participation once but play **96 matches** between them, so a per-result fee that looks small beside the trophy is a bigger line than the trophy is. An earlier draft of this change sized the pot in a comment and was out by ~40% for exactly that reason. `scripts/continentalPrizeProbe.ts` prints the pot by stage, per-club earnings against `PRIZE_TOP_5`, and earnings per country as a share of base income — size a retune on that, not on arithmetic.
  - **Deliberately NOT scaled by `financeScale`** (user call), which is what the game already did and what UEFA does: a Belgian club earns exactly what an English one does. That flatness *is* the feature — it is why Europe is transformative for a small-league club — and it is simultaneously the risk, since a rich weak-league club climbing the ladder is this file's most-repeated tripwire. Hence the audit below is the gate for any change here.
  - **Measured `scripts/weakLeaguesAudit.ts`, 20 seasons x 4 seeds, against the same script run on the merge base — and the first thing that run establishes is that MAIN ITSELF FAILS IT.** Baseline: **3 of 4 seeds end in deficit** (Turkey -£5.1M s21, Serbia -£3.6M s20, Serbia -£6.7M s20), ladder OK on all four. **The "SOLVENT on 4 of 4" record higher up this file is stale** — something between that measurement and #309 regressed it, and anyone tuning here who assumes a green baseline will misread their own change as the cause. Measure the merge base first, every time.
  - **Verdict: the ladder is clean, solvency is a wash, and the pot is 3.3x.** Ladder OK on every seed on both sides; mean **BIG4→Serbia 7.47 → 7.89** (the headline block spread *widens*) and France→Serbia 5.16 → 4.37, both inside their gates — so the feared weaker-but-richer inversion, the whole risk of paying flat, **did not happen**. Solvency: deficits go **3 of 4 seeds → 4 of 4**, but every one of them is *smaller* — **worst case -£6.7M → -£3.4M and the total shortfall -£15.4M → -£10.1M, down a third**. So it neither fixes nor meaningfully worsens a pre-existing failure; it spreads a smaller total more thinly. **The one rung to watch is France→Netherlands, mean +2.09 → +0.17** (per seed +0.17/-0.89/+0.08/+1.31): it passes, but it is a 3-point "resolvable" rung that has nearly collapsed on the mean, and it is the first thing that will fail if these constants go up again.
  - **Why the poorest leagues still run deficits even though their clubs are the ones this pays**: only 4 of a 16-club league reach Europe, and the other 12 compete in a wage market the 4 have just been enriched in. That is the real-life dynamic (European money creates *domestic* inequality) and it means European prize money is not a lever for weak-league solvency, whatever its size. Don't reach for it as one.
  - **Measured pot (`continentalPrizeProbe.ts`, seed 7): Cup £527M + Shield £167M = ~£694M a season, against ~£211M before — 3.3x**, over 56 of 420 clubs. Per qualifier that is **14-16% of a big-four club's base income and 25-31% of Serbia's, Scotland's or Greece's**, monotonically increasing as the league gets poorer, which is exactly what paying flat means. Cup per-club: min (league-phase exit) £10.5M, median £14.5M, champion £45.5-47M. **Note this is well above the "roughly 2x" the change was scoped at** — the scoping arithmetic under-counted the 96 league-phase matches, which is the same trap this entry's third bullet warns about, made while writing this entry. Participation alone is £320M of the £527M, so trimming the per-result fees cannot get back to 2x; `CUP_PRIZE_PARTICIPATION` is the lever if it ever needs to.
  - **The obvious next idea is a coefficient-weighted "value pillar", and it was left out on purpose.** It is UEFA's biggest pillar and the game already computes country coefficients (`core/cup/coefficients.ts`), so it is tempting and cheap to build. It also closes a **feedback loop that file explicitly names as its failure mode to watch** — places won → money → strength → coefficient → places won. If it is ever added, gate it on `coefficientAudit.ts`'s churn metrics (`changes-per-dynasty`, `at floor`), not just on solvency.
  - **No persisted field and no migration** — these are read at sim time. The `touchStats` scoreline hash is untouched, for the documented reason: that baseline runs `simSeason` (`core/season.ts`), which contains **zero** cup references. Budgets do feed AI market decisions, so multi-season dynasties diverge from a pre-change baseline; single-season results do not.

**Continental Shield** (2026-08-19) — the second continental competition, the Europa League to the Cup's Champions League. **Structurally the Cup with different numbers**: everything that differs lives in `CUP_FORMATS` (`constants.ts`), keyed by `CupState.competition` (`"continental" | "shield"`) and read through `cupFormat(cup)`. State is `LeagueStore.shield`/`shieldHistory`, built and archived beside the Cup in `simOffseason`, advanced by the same `advanceCompetition` path in `simThrough`. Page is `/shield` — the *same* `Cup` component with a `competition` prop.
- **Field: strong leagues' 5th–6th, weak leagues' 3rd–4th = 16 clubs.** Where the Shield starts in a league is **derived**, by summing what every competition above it takes from *that same league* (`cupOffsetForCompetition` over `CONTINENTAL_ORDER`) — not a stored per-format offset, which would silently overlap or leave a gap the moment a league carried its own slot count (`Competition.continentalSlots`). It shipped as a `strongOffset`/`weakOffset` pair and this file described it that way for a while; the derivation replaced it. Since 2026-08-28 disjointness no longer rests on the offset at all — see the Cup's qualification bullet.
- **Both competitions share the Cup's matchdays** (LP 3/7/11/15/19/23, playoff 27, KO legs 29/31, 33/35, 37) — sound *only* because the fields are disjoint, and it's what the real midweek calendar does. No calendar work, and no fatigue interaction (cup matches already build their own per-matchday composites).
- **A 16-club field needed no change to `leaguePhase.ts`**: two pots of 8 against 3 games per pot ✓, and `splitLeaguePhase` lands exactly (4 direct QF / 8 playoff / 4 out).
- **Every cup rng stream is salted per competition** (`CupFormat.streamTag`, continental **30** = the literal it shipped with, shield 70; plus a separate `drawSeed`). Two cups in the same season on the same matchdays would otherwise draw *identical* streams round for round. Any third competition must take its own tag.
- **Each competition pools its own normalization baseline.** Pooling the two fields together would measure Shield clubs against Cup clubs, which is the comparison neither makes.
- **Prizes ≈ 40% of the Cup's** (`SHIELD_PRIZE_*`): champion ~£20M vs the Cup's ~£47M, front-loaded the same way (see **Continental prize money**). The relationship these were sized to hold — finishing 5th and winning the Shield must not out-earn finishing 4th and going out of the Cup's league phase — **was false as shipped and is only closer now**: the Shield champion took ~£21M against a Cup league-phase exit's £2M, because the exit paid almost nothing. Front-loading both narrows it to ~£20M vs ~£14M. Closing it outright would mean paying a Cup league-phase exit more than a Shield champion, which is its own call about how far apart the competitions should sit.
- **Held as its own `LeagueStore` field, not a list of cups** — `cup` has ~30 readers across sim and UI and a list turns every one into a lookup. Revisit only if a third competition arrives.
- **Deliberately NOT wired into the worldwide awards.** `worldAwards.ts` reads `ctx.cup` only, so Shield matches score zero there (exactly what already happens to every non-Cup player; their league seasons still count in full). The cup component is delicately balanced — `WORLD_AWARD_CUP_MULTIPLIER` is 1.0 for measured reasons and the team bonuses trade directly against winner's world-ovr rank — so adding an unmeasured second competition is the move those comments warn against. Needs a `scripts/worldAwardsAudit.ts` run before it goes in.
- It *is* wired into club history, the Frivolities trophy cabinet and both GOAT boards (`GOAT_SHIELD_TITLE_WEIGHT` 8 vs the Cup's 25; `GOAT_TEAM_SHIELD_TITLE_WEIGHT` 40 vs 150), a profile honour pill via `playerHonors.ts`'s `HonorCups.shieldHistory`, and `freeAgentCull` scrubs its box-score lines like the Cup's.
- **Merged with domestic cups (#244) on 2026-08-20; the two were built in parallel and touch the same dozen integration points.** They compose cleanly, and the two facts that make that true are worth keeping: the domestic tie stream is `0x0d0d` against the Shield's tag 70 (so no stream collides), and `DOMESTIC_CUP_MATCHDAYS` `[5,9,13,21,26,36]` is disjoint from the continental calendar (so a club can hold all three at once and never double-book). A club's trophy total now counts league + Cup + Shield + domestic + tier 2; **a treble is deliberately league + Cup + domestic and does NOT include the Shield** — the Shield is what you win instead of the Cup, so a "treble" containing it would be the wrong shape.
- Old saves backfill `shield: null` / `shieldHistory: []` and pick a Shield up at their next offseason (qualification needs a finished table), exactly as pre-cup saves did for the Cup. `scripts/shieldProbe.ts` verifies the whole thing end to end on a simmed world (field sizes, zero overlap, which places each drew from, distinct champions and scorelines).
- **Prize money is the Shield's ONLY channel into the world, and that was proved rather than argued.** Set every `SHIELD_PRIZE_*` to 0 and a 4-season dynasty comes out **bit-identical to `origin/main`** (same per-country mean OVR to 0.1, same rung gaps to 0.01, same min AI budget). So the Shield adds no rng-stream contamination, no fatigue, no availability effect — it plays its matches on salted streams and touches the league solely by crediting budgets. **Re-run that check after any change here**; it is cheap (two 2-minute runs) and it is the fastest way to catch a competition accidentally reaching into the league stream.
- **The ladder was audited against `origin/main` and shows no systematic effect** (`scripts/weakLeaguesAudit.ts`, 10 seasons × 4 seeds, the identical script run on both branches). Solvency holds on **8/8 runs**. The rung that looks alarming is Belgium→Turkey, and it is the documented coin-flip pair: shield `−2.04 / +0.51 / +0.12 / +2.04` against main `+0.51 / −1.07 / −0.66 / −0.10`, i.e. the **sign flips by seed on both branches** and the Shield's cross-seed mean (**+0.16**) is *better* than main's (**−0.33**). Block spreads likewise: BIG4→Turkey mean **5.10 vs 4.86**, BIG4→France **2.71 vs 2.10**, France→Turkey **2.39 vs 2.76** (all well clear of their gates). **Seed 1 alone reads as a gross inversion on the Shield branch and is noise** — the exact trap the audit's two-scale design (per-seed catches gross, mean-across-seeds catches systematic) exists to avoid, and a reminder that a 4-seed range is not a variance estimate. Caveat worth keeping: this is **10 seasons, not the documented 20**, so it is evidence of no *large* effect rather than a full dynasty clearance; `SEASONS=20 SEEDS=1,2,3,4` is the real gate if the prizes are ever raised.

**Continental cup formats (God Mode, `core/cup/cupShape.ts`, `LeagueStore.continentalFormats`, 2026-09-16, user ask; away goals and field size added 2026-09-21)** — per competition (Cup / Shield / Americas Cup): opening stage (Swiss league phase / groups of four / straight knockout), Swiss games 4/6/8, knockout size (auto / SF / QF / R16), playoff round on/off, one or two legs, **away goals on/off**, and **how many clubs are in it**. God Mode's Cup Formats tab (presets + plain-language preview). Every setting but the size leaves qualification untouched — a format changes how a field plays, never who is in it (a straight knockout trims a field above 32); **the size setting is the one exception and deliberately changes who qualifies.**
- **A default-format cup is built byte for byte as before.** `buildCupState` only takes the custom path when the settings differ from `DEFAULT_CONTINENTAL_FORMAT`, and only custom cups carry the new optional `CupState.shape` / `calendar` / `CupLeaguePhase.groups`. `continentalFormats.test.ts` pins default-equals-no-settings. No migration; absent = shipped.
- **The cup records its shape and calendar at the draw**, so a mid-season settings change takes effect next season and can never reshape a competition in progress. Every reader that used a calendar constant or `cupKnockoutPlan` goes through the cup (`koLegMatchdays`, `cupSplitPlan`, `seedKnockoutFromLeaguePhase`), so a stored calendar wins.
- **Calendar is derived backwards from a final on matchday 37** (`buildCupCalendar`): two-legged rounds 2 apart, single-leg 3 apart (exactly the shipped spacing), playoff 2 before the first knockout leg, opening rounds spread over the free days before that; it skips `DOMESTIC_CUP_MATCHDAYS` and deadline day, because a club can be in both competitions. Six opening rounds that fit reuse the shipped league-phase days.
- **Both non-Swiss openings reuse the league-phase record, which is what kept the blast radius small.** Group games are ordinary `LeaguePhaseMatch` rows plus `leaguePhase.groups`, so stats, prizes, coefficients, archiving and the schedule needed no change; a straight knockout has a league phase with `matches: []` holding the field. **Trap:** a cup with `leaguePhase: null` reads as a *legacy* bracket (`isSwissCup`), so the knockout opening must keep a league phase. Its entry fee is paid on its first tie (`payKnockoutOpeningEntry`), mirrored in `prizeIncome.ts`.
- Groups: top two per group plus best thirds to fill the bracket (auto = nearest power of two to 2 x groups, so 24 → Euro-2016 R16); a repair pass stops a group's two qualifiers meeting in the first round.
- **Round prizes and coefficient round bonuses count back from the final for custom cups only** (`koWinPrize`; R16 win = half a QF win). Shipped cups keep `byRound[tie.round]`, which is **wrong for a hand-built world whose bracket opens at the semi-finals** (a SF win pays the QF prize). Pre-existing, deliberately left so no existing save's money moves.
- **Away goals (`ContinentalFormatSettings.awayGoals` → `ResolvedCupShape.awayGoals` → `resolveTwoLeggedTie`'s `TwoLegRules`)** — a level aggregate goes to whoever scored more away from home, **extra time included**, which is the real pre-2021 UEFA rule rather than a 180-minute simplification: extra time is played at the second leg's ground, so goals the *visiting* side scores in it are away goals too, and since the aggregate can only still be level if both scored the same, any extra-time score at all sends the visitor through. `CupTie.decidedByAwayGoals` is optional and absent on every other tie, so nothing migrates. **The direction is the silent trap**: the tie's `home` hosted leg 1, so HIS away goals are leg 2's and `away`'s are leg 1's — reversed, the rule still picks a winner, always the wrong one, so both the code and `awayGoals.test.ts` name the two quantities rather than inlining the comparison. `levelGoesTo` (the Liguilla rule) is checked first; nothing passes both.
  - **It DOES shift the rng for later ties in the same round, and `levelGoesTo`'s docstring's reasoning does not cover it.** That comment says skipping extra time is safe "because every caller passing this runs the tie on a stream of its own" — true of the title playoff, false here: `playKnockoutLeg` gives one stream to a whole round, so a tie the rule settles early moves every subsequent tie's draws. Inherent to the rule (a cup playing it is a different competition), off by default, and it is why the setting can only be chosen at the draw.
- **Field size is applied as a `SlotOverrides` map (`continentalSlotOverrides`), NOT by trimming the field at the draw — and that choice is the whole feature.** Trimming can only shrink; rescaling each league's places makes a *bigger* competition real, because every league simply sends more of its table, and the competitions below slide down underneath (the Shield's entry point is derived from the slots above it, so a 48-club Cup pushes it from 5th–6th to 9th–10th with no code). It also composes with the country coefficients by construction — they re-sort places between countries zero-sum, then the size scales that allocation — and reaches `cupPlan`, the allocation, `cupOffsetForCompetition`, `cupSlotRange`, the Standings shading and the Cup page legend for free, because all of them already ask `cupSlotsForCompetition`. Rescaling is proportional with largest remainder (ties on compId, so it is order-free), which keeps the ladder: a big-four league still sends double a weak one at every size. Capped per league by the clubs it has left after the competitions above it.
  - **Four things must agree on the number and they disagree SILENTLY.** `cupPlan` promises a total, the allocation produces a field, `qualifyCupTeams` trims to the plan and `buildCupState` returns **null** on a mismatch — i.e. the competition simply does not exist that season, with nothing thrown and nothing logged. `cupPlan`/`worldHasCup`/`qualifyCupTeams` therefore all take the overrides, and `continentalSize.test.ts`'s "promises exactly the field the allocation then produces" is the assertion standing between a resized cup and a missing one.
  - **All three override call sites must wrap the same way** — `offseason.ts` (the draw), `cup/seasonQualification.ts` (the live Standings projection) and `continentalNews.ts` (the feed). Miss one and the table shades a place the draw then doesn't award.
  - Sizes offered are multiples of four from 12 to 64, which is exactly what `isValidCupFieldSize` accepts, so a chosen size survives `cupPlan`'s `largestValidCupField` trim untouched; `snapFieldSize` snaps a hand-edited save's number down rather than refusing it.
- User-set and sandbox-only, so no dynasty audit; a non-default format does move prize money (more or fewer paid stages), which is the documented weak-league tripwire if this is ever offered outside God Mode. `scripts/continentalFormatProbe.ts` runs all three competitions in custom formats through a real season, and `scripts/continentalSizeProbe.ts` does the same for the size and away-goals settings (measured seed 7: Cup at 48, Shield at 16, Americas Cup at 12, all drawn and run to champions, fields disjoint, 5 ties decided on away goals). **Harness note for both: `simThrough` halts before the user's cup final, so one call does not reliably finish a season — loop until `phase === "offseason"` rather than calling it once.**

**Domestic cups** (`core/domesticCup/`) — one open-draw knockout per country, both tiers, so a club can win the treble
- **One cup per country, contested by all 40 clubs** (tier 1 + tier 2), stored as `LeagueStore.domesticCups` (this season, one per country) and `domesticCupHistory` (archived at offseason rollover). Unlike the Continental Cup **nothing qualifies**, so cups run from **season 1** and `createLeagueState` builds them; the offseason archives the finished ones and builds next season's off the same `tablesByCompId` the Continental Cup uses. Reuses `CupTie` and `resolveCupTie` outright — a domestic tie and a European one are resolved by identical code.
- **Open draw, redrawn every round — so only the drawn rounds exist.** `DomesticCupState.rounds` grows one entry at a time: `advanceDomesticCup` records the played round and draws the next from `[...byes, ...winners]` (`drawPairings`, a Fisher-Yates shuffle, home = whoever comes out first). There is deliberately no bracket to render in advance, which is what makes it a domestic cup. Draw stream is `hashInts(season, compId, round, DRAW_STREAM)` — **no lid**, so a cup drawn at league creation (lid still 0) and one drawn in the offseason use the same rule; ties play on `hashInts(lid, season, compId, round, DOMESTIC_TIE_STREAM)`. Never the shared `rng`, so **league scorelines are untouched** (`touchStats` hash unchanged — that test runs `simSeason`, which has no cups at all).
- **The field isn't a power of two, and `prelimTieCount` is where that's handled.** 40 clubs → `totalRoundsFor` 6 and 8 preliminary ties: the **worst-ranked 16** play, the other 24 get byes, 32 remain. Ranking is `(tier played in LAST season, finishing position)`, so a relegated club outranks everyone already in tier 2 and a promoted one sits atop the tier-2 block — the only thing this ordering decides is who enters early. No tables at all (season 1, fresh import) → tid order, which is the tier-1 block then the tier-2 block. **An exact power of two must return 0 prelim ties** or a full opening round gets labelled "preliminary" (caught by a test).
- **Round identity is distance from the final, never the round index** — `domesticRoundName` and `domesticPrizeForRound` both key off `roundsFromFinal`, and `DOMESTIC_CUP_PRIZE_BY_ROUNDS_FROM_FINAL` is indexed `[0] = lifting it`. Same reason `cupRoundsFromFinal` exists for the Continental Cup: a cup with a preliminary round and one without must pay the same for a semi-final.
- **Composites pool the WHOLE country (both divisions), and this is load-bearing** — the identical lesson as `cupMatchData`. Composites z-normalize within a competition, so a tier-2 club measured against its own division reads as an average side and would meet a top-flight club as an equal. `simThrough` builds one `leagueMatchData` over all 40 clubs per cup matchday. Measured on a simmed season: **9 of 64 quarter-finalists were tier-2**, and all 8 champions were tier-1 — upsets happen without being cheap.
- **`DOMESTIC_CUP_MATCHDAYS` = [5, 9, 13, 21, 26, 36]**, every one clear of `CUP_LEAGUE_PHASE_MATCHDAYS`/`CUP_PLAYOFF_MATCHDAY`/`CUP_KO_LEG_MATCHDAYS` (a test asserts this), of deadline day, and of the finale. A smaller field takes the **last** n, so the final never moves. `simThrough` also **halts before the user's domestic final** (matchday 36), same as the Continental final on 37.
- **The cup paid NOTHING until 2026-08-31, and that was a measured decision — see the re-enablement entry below for what ships now, and read this one first for why the numbers are small.** It shipped with real prizes first (12M down to 0.25M per round, runner-up 3M, each ×`financeScaleFor` so a weak league could not out-earn a strong one). `scripts/weakLeaguesAudit.ts`, 4 seeds × 20 seasons, **against the same script run on the merge base**: the **ladder held** everywhere (per seed and on the 4-seed mean, so the financeScale scaling did its job) but **2 of 4 seeds went into deficit** — Belgium −£0.5M s20, Turkey −£1.4M s19 — where the baseline is solvent on all four. That is precisely the result that got the need-buy tightening rejected, and the documented failure shape: **the finance column fails first, not the ladder.** The audit cannot separate the two candidate mechanisms (a one-off prize converted into a permanent wage liability — both deficits land late — versus plain stream shift, since crediting a prize before the winter window moves every downstream AI market decision and the weak leagues already sit within ~£0.01M of zero at their thinnest). **At zero, `creditPrizes` is never reached, no budget is touched, and a dynasty is bit-identical to one with no domestic cups at all — verified, seeds 1 and 3 reproduce the baseline's 20-season numbers exactly, to every decimal.** That is what made shipping the competition provably safe, and it is no longer true: the prizes are live, so a dynasty is **not** bit-identical to one without domestic cups, and that bit-identity check is gone as a tool. `domesticCupIntegration.test.ts` pins the payout structure rather than the zero.
- **Archived like the Continental Cup** (`archiveDomesticCup` folds every round's box scores into `statLines` and drops them) — 39 ties per country per season × 8 countries is a lot of box scores to keep forever, and save size is what freezes the game. `cupStats.ts` was refactored so both cups share `aggregateBoxScores`/`lineFromBoxScores` rather than growing a second copy. `freeAgentCull` scrubs both shapes; `migrate.ts` backfills `[]` and deliberately **does not** build a cup mid-season (half its matchdays are already gone) — an existing save gets one at its next offseason.
- **The Ballon d'Or pays for winning it — as a TEAM bonus only (`WORLD_AWARD_DOMESTIC_CUP_BONUS` 0.25, pro-rated over `WORLD_AWARD_DOMESTIC_CUP_FULL_INVOLVEMENT` 4 ties).** Added because the award already paid `WORLD_AWARD_LEAGUE_TITLE_BONUS`, so a double-winner was credited for one trophy and not the other; 0.25 ≈ 3 striker goals against a title's ~10, the intended hierarchy (World Cup > Continental > league > domestic cup). **No domestic cup goals/assists/ratings enter the award, and that is the load-bearing part**: those ratings z-normalize within one country, so they carry exactly the weak-league bias `leagueStrengthOffsets` exists to remove, and no correction is available for them (the Continental Cup escapes this only because `cupMatchData` pools its whole field). A uniform squad bonus has no such bias — it can move the award *between* clubs but never lift a player above a better team-mate, the same property that made raising the other team bonuses safe. `BallonDOrEntry.domesticCup` is **optional** so every persisted pre-feature entry still typechecks and reads as 0; `WorldAwardContext.domesticCups` likewise, so `migrate.ts`'s backfill scores old seasons exactly as before rather than re-ranking them on a trophy nobody played for. Second-tier winners count (unlike a tier-2 league title, which `championTidByCompId` excludes). **Measured** (`worldAwardsAudit.ts`, 3 seeds × 12 seasons, against the same script with the term removed — world awards feed nothing in the sim, so both runs play identical dynasties and only the ranking can move): winner's median world-ovr rank **69 → 68**, ST share **69% → 69%**, league-title rate **72% → 72%**, Continental-win rate 28% → 25%, mean score split league 12.45 / cup 0.95 / title 0.55 / intl 0.55 / **dcup 0.04**. It is a **tie-breaker-scale** term by design and flipped one or two winners in 36 seasons; the guarded metrics held. The audit now reports a `dcup` column and a "won domestic cup" rate — note that rate reads 0 on any build without the term, since it keys off the optional field, so it is not a before/after comparison on its own.
- **Domestic cup prize money, re-enabled 2026-08-31 at ~1/5 of the rejected numbers, PLUS a glamour-tie payment that is the actual feature.** The table above records why these shipped at zero. Re-enabled because a real domestic cup *is* small money — the FA Cup's whole fund is ~£16M and winning it pays ~£3.9M against a league title's ~£60M merit payment — so the old £12M-a-round table was ~3.6x too generous *as football*, quite apart from bankrupting two seeds. A winner's run is now **~£3.3M** and a country's pot ~£11.7M before scaling.
  - **Scaled by country but FLAT ACROSS TIERS, which needed its own `domesticCupScaleFor`** rather than `financeScaleFor`. The country half is realistic (domestic broadcasters) and is the direction that protects the ladder. Dropping the tier half is the point: the real cups pay a fourth-tier club exactly what they pay a champion for the same round, this cup fields **every** division of a country, and taxing a lower-division run by `tierScale` (`DIVISION_2_BUDGET_SCALE ** (tier-1)`, so 0.36 at tier 3) deletes the only part worth modelling. Opposite call from the continental competitions, which pay flat because UEFA does.
  - **The prize table alone did NOT serve the feature's purpose, and only measurement showed it.** With prizes and no glamour payment, `domesticCupPrizeProbe.ts` read the median tier-2 club that earned anything at **0.3% of its season**, while the one or two who won their cup outright took **20-27%** — and that money is not the prize table at all, it is the **Continental Shield place** a cup win earns (`allocateContinentalPlaces`), collected the following season and made ~4x more valuable by the same day's continental reshape. So the competition was a **lottery**: one transformed club a year and ~100 others getting nothing. Do not read "a tier-2 club took 27%" as the prize money working.
  - **`DOMESTIC_CUP_GLAMOUR_TIE_BONUS` (£300k) is the fix**, paid to the **smaller club only** in any cross-tier tie, **win or lose**, and **multiplied by how many divisions separate them** (added flat, made per-gap on 2026-09-01 when the world gained a third division — a tier-3 club drawing the top flight is the competition's most romantic tie and must not price the same as a tier-2 club drawing the division immediately above). It models the one real mechanism by which lower-division clubs profit from a cup: gate receipts from drawing a giant, which are taken on the day and do not care about the result. Only the smaller side is paid because a cup gate is a rounding error to a top-flight club, so paying both would double the money entering the world to buy no gameplay — targeting it is what lets it be big enough to matter. Measured effect on the **three-division** world (`domesticCupPrizeProbe.ts`, seed 7, seasons 3-5): lower-division clubs earning anything **300-315**, median **0.9% of a season**, best cases a Scottish tier-2 club at **24.1%**, a French tier-3 club at **12.8%** and a German tier-3 club at **11.9%** — and a tier-2 club won its country's cup outright in every season sampled, taking the Shield place. **A gradient instead of a lottery, which is the half of the purpose that survives.**
  - **The pyramid does NOT pay downward at £300k, and losing that was the price of clearing the ladder gate — do not re-quote the £600k figure.** At **£600k** the money per club that earned anything ran **tier 1 £0.54M, tier 2 £0.60M, tier 3 £0.66M**: the third division genuinely out-earned the top flight, which was this feature's headline result. At the shipped **£300k** it reverses to **tier 1 £0.48-0.51M, tier 2 £0.38-0.41M, tier 3 £0.34-0.39M**, top flight highest in all three seasons sampled. The mechanism is a straight tug-of-war and is worth understanding before anyone retunes: the **prize table** rewards going deep, which top-flight clubs do, while the **glamour bonus** rewards being small, and halving the latter handed the balance back to the former. So the shipped state buys *breadth* (300-plus lower-division clubs earning something rather than one lottery winner) but not *tilt*. Recovering the tilt means either a larger glamour bonus — which is what broke `Turkey→Greece` — or a **smaller prize table at the same glamour**, which is the untested configuration and needs its own 4-seed audit.
  - **The structural caveat, which no tuning fixes:** this game's lower divisions earn **60%** and **36%** of their top flight (`tierScale`) where real football's third tier earns ~1%, so a realistic cup cheque can never mean to these clubs what it means to a real one. £300k is ~0.6% of an English tier-2 club's £52.8M season and ~0.9% of a tier-3 club's £31.7M. Going much further prices the cup above the league places beside it; the honest ceiling here is "funds a signing".
  - **Cost on the 626-club world: domestic £0 → ~£180M a season, 0.74% of world base income** — the denominator that matters, since against *prize* money alone it reads 21%, which overstates it badly. World base income is **£24.3bn** (`scripts/worldBaseIncomeProbe.ts`, which sums `BASE_SEASON_BUDGET` over every club scaled by country and tier); the continental pot beside it is ~£694M, i.e. **2.85%**. Measured on top of the continental reshape by `scripts/domesticCupPrizeProbe.ts`, which reports the **combined** total, since two probes each reporting half cannot answer what the audit reacts to.
  - **The first audit FAILED at £600k, and halving it is what fixed it — which is also the only evidence that magnitude is the lever (2026-09-02).** `weakLeaguesAudit.ts`, 20 seasons x 4 seeds, both sides re-measured on the 626-club main. At **£600k**: `Turkey→Greece INVERTED on the mean (-1.71 < -1)`, and **not as a re-roll** — the rung is negative on *all four* seeds (-2.80 / -1.50 / -1.56 / -0.96) where the baseline is mixed and positive on the mean (+0.25). That is the documented weaker-but-richer tripwire, tripped by this feature's own money. At **£300k** the same rung reads **-0.26** (+0.89 / -2.47 / -0.91 / +1.47), signs mixed again like the baseline. **Halving the money roughly halved the distortion — a dose-response, and the thing that actually identifies magnitude as the lever** rather than the assertion it was before this.
  - **Shipped verdict at £300k: every gate passes on the pooled four-seed mean, and every seed reads `ladder OK` on its own.** Converged rungs (mean, baseline → treatment): Portugal→Belgium +1.14 → **-0.52**, Belgium→Turkey +0.88 → **+0.95**, Turkey→Greece +0.25 → **-0.26**, Greece→Scotland -0.58 → **+0.89**, Scotland→Serbia +1.43 → **-0.36** — every one inside the ±1 tolerance, and moving in both directions rather than uniformly down, which is what the converged block's documented coin-flip looks like. Resolvable rungs stay positive on all four seeds: BIG4→France +3.95 → **+3.96**, France→Netherlands +1.76 → **+1.70**, Netherlands→Portugal +1.44 → **+3.44**. Block spreads narrow slightly and stay far clear of their gates: BIG4→Serbia +10.27 → **+9.81**, France→Serbia +6.31 → **+5.85**. **Pool the per-seed values by hand** — a one-seed invocation applies the mean gate to a single draw and seed 4 duly reports Belgium→Turkey "BROKEN" at -2.03, which is the documented misuse, not a verdict.
  - **Solvency is NOT a wash, and the honest reading is that it is slightly worse.** Both sides run **4 of 4 seeds in deficit** — main has been red on this gate since #308, so do not assume a green baseline — with comparable worst cases (baseline -£3.3 / -£9.7 / -£3.4 / -£7.9M, treatment -£12.4 / -£5.7 / -£0.7 / -£8.1M). What moves is *frequency*: **any club in deficit at 10 of 168 sampled points on main against 19 of 168 here**, on a similar worst-at-once count (1-3 clubs of 625 either way). This is the pre-existing weak-league wage ratchet being fed a little harder, not a new failure — and it did **not** respond to halving the money (v1 and v2 are indistinguishable on solvency where the ladder halved cleanly), which is exactly what marks it as a re-roll rather than dose-responsive.
  - **Two mechanisms were proposed for the £600k failure and NEITHER survived measurement — record this before proposing a third.** (a) *"The bracket is capped at 32 clubs, so a smaller country splits the same late-round pot among fewer clubs"*: **refuted.** Scale-adjusted domestic money per club is nearly flat across the world (£0.54-0.78M), and Greece vs Turkey is £0.63M vs £0.61M, a **3%** gap where the theory predicted ~33%. (Scotland's £0.78M *is* a real size effect — 32 clubs exactly, so no preliminary round and every tie pays — but Scotland is not the rung that broke.) (b) *"The late rounds concentrate on top-flight clubs, which is what the gate reads"*: **unproven.** Money per top-flight club does read Greece £0.54M against Turkey £0.40M, the right direction, but across all twelve it spans £0.39-0.55M **without tracking top-flight size** — the Netherlands has 18 clubs and the highest figure, Scotland has 12 and one of the lowest — and it is a single season of a single seed, so most of that spread is draw noise. `domesticCupPrizeProbe.ts` prints both tables.
  - **So magnitude is the only evidence-backed lever and the mechanism is still unknown.** The honest experiment nobody has run is glamour-bonus-only against prize-table-only, two audits; until someone does, treat £300k as *calibrated* rather than *understood*, and re-measure both sides before raising it.
- **Treble** = tier-1 title + Continental Cup + domestic cup in one season, derived in `clubHistory.ts` (`ClubSeasonRecord.treble`, `ClubHistory.trebles`). Domestic titles also feed the Frivolities trophy cabinet, both GOAT boards (`GOAT_DOMESTIC_CUP_TITLE_WEIGHT` 6 / `GOAT_TEAM_DOMESTIC_CUP_TITLE_WEIGHT` 40 — deliberately the cheapest trophy: six games can win it), and **`playerHonors.ts` now credits cup wins at all**, which it never did — `computePlayerHonors`/`computeArchivedHonors` take an optional `HonorCups` and return `continentalCups`/`domesticCups` alongside `leagueTitles`, so the Continental Cup gained a profile pill in the same change.
- UI: `/domestic-cup` (country + season dropdowns, rounds as columns), a Domestic Cup stats tab on Player Profile, Schedule rows (`kind: "domestic"`), a Dashboard final warning, and the sim ticker — which needed `MatchdayProgress` to gain a `domesticTies: DomesticTieResult[]` argument (through the worker protocol), because a `CupTie` carries only a round *index* and the ticker had "Continental Cup" hardcoded.

**Continental regions and the Americas Cup** (`ContinentalRegion`, `competitionRegion`, `CUP_FORMATS.americas`, 2026-09-12)
- **Every continental competition belongs to a region (`CupFormat.region`) and only draws from that region's top flights.** Before this nothing in the game knew about continents, so adding an American league would have put Brazilian clubs straight into the European Continental Cup. `Competition.region` is optional (absent → `COUNTRY_REGION`, else `"europe"`), so no save carries it and no migration was needed.
- **The gate is in `cupSlotsForCompetition`, BEFORE every override**, including a league's own `continentalSlots` and the coefficient `SlotOverrides`: a region is a hard boundary, not a default. `cupPlan` filters its strong/weak split by region too. `resolveLeagueSpec` reports zero European slots for a non-European league so `worldTuningWarnings` doesn't count it toward the Cup, and warns separately about the Americas Cup field.
- **The coefficient is Europe-only (`coefficientLeagues`)**, and this is load-bearing rather than tidy: an American league holds no Continental Cup places, and a zero anywhere on the ladder switches off `COEFFICIENT_MIN_CUP_SLOTS` for every league (`reallocateCupSlots`). Filtering it out keeps the European reallocation byte-identical. The Americas Cup's places never move — four fixed countries have nothing to rank.

It takes BOTH routes the European pair splits: holder keeps his place, and a country's domestic cup winner takes one of the four. `CONTINENTAL_ORDER` is `["continental", "shield", "americas"]`; the one-pass `placed` set is what keeps fields disjoint.

**Staged playoffs: a round per sim block after the season** (`core/playoffStages.ts`, worker `{type:"playoffs"}`, `PlayoffStageCard`, 2026-09-14, user ask)
- **The game draws every title and promotion playoff when the season ends and plays them a round per click**, the way the World Cup is played a stage at a time. Only the worker asks for it (`simThrough`'s trailing `options.stagePlayoffs`); every headless caller — tests, audits, `jumpSeasons` — keeps the single pass, and `simOffseason` finishes any rounds left unplayed through `completeTitlePlayoffs`/`completePromotionPlayoffs`. So nothing measured in `scripts/` moved.
- **Staged and single-pass land on identical results, and that is pinned rather than argued** (`playoffStages.test.ts` deep-equals them). It holds because every tie keeps its own `(lid, season, comp, round, tie)` stream and the round functions (`playTitlePlayoffRound`, `playPromotionPlayoffRound`) keep the bulk bracket's tie indices; the bulk functions are now just loops over them. The one thing staging adds on purpose: match data is rebuilt from the squads as they stand each block, so a lineup the user sets between rounds is the one he plays with.
- **A block plays one round in every playoff with the MOST rounds left**, so brackets of different depth line up on their finals: MLS's wild card alone, then MLS round one + Argentina's round of 16, quarter-finals, semi-finals (English promotion semis join here), then every final including the German ties. 5 blocks in the shipped world. Same alignment the confederation cups use.
- **`reviewSeason` moves to the block that decides the last playoff** (`playPlayoffStage`), because "did we win the league" and "did we go up" aren't answerable before. `simThrough` skips it when staging left anything to play; its own double-review guard (`lastVerdict.season`) covers any overlap.
- **`playoffsPending` is derived, like `isIntlStagePending`, not a new `phase`** — and it takes precedence over the international stages on the Dashboard, TopBar and SpectatorDashboard, since the playoffs close the club season. "Sim through the playoffs" (`simThroughPlayoffs` with `stopBeforeUserRound`) stops before any block the user's club plays in, but always plays at least one, so pressing it on your own round plays it.
- A playoff in progress has `winnerTid: null`; `playoffOutcomes`, `titleChampions` and promotion news already skipped those. No persisted field changed and no migration.

**Title playoffs** (`core/titlePlayoff.ts`, `COUNTRY_TITLE_PLAYOFF`, `competitionTitlePlayoff`, 2026-09-12)
- **A top flight can decide its CHAMPION in a top-8 knockout** (1v8, 4v5, 2v7, 3v6; QF, SF, final): `"single"` (higher seed hosts; Argentina, US) or `"two-legged"` (higher seed hosts leg 2; Mexico's Liguilla). **Mexico uses the Liguilla's real tiebreaker**: in the QF and SF a tie level on aggregate goes to the higher seed outright, with no ET, no pens and no away goals (`resolveTwoLeggedTie`'s optional `levelGoesTo`, which sets `CupTie.decidedByTablePosition`); only the final goes to ET and pens. Every cup omits the argument, so cup ties are bit-identical. Single-leg level games (Argentina, US) go to ET and pens. Skipping ET/pens changes only the draw count inside a title-playoff tie's own seeded stream, so no other result moves.
- **Only one fact moves: `SeasonHistoryEntry.championTidByCompId`.** Prize money, hype, continental places, relegation and the board's expectations all still read the table, which is also what the real leagues do. That made the change almost free — every honours surface already read the recorded champion — EXCEPT the four places that re-derived "champion" as "top of the table": `clubHistory` (`champion: position === 1`), `frivolities/clubs.ts`, `teamGoatRanking` and `trebleCountByTid`. All four now prefer the recorded tier-1 champion and fall back to the table only for lower divisions and entries without one. **Any new "who won the league" derivation must read `championTidByCompId`, not `table[0]`**, or it silently disagrees with the title playoff.
- **Shaped exactly like the promotion playoff**: played at the season boundary in `simThrough` on end-of-season squads (sharing one `finalTables` computation with the promotion playoffs), replayed by `simOffseason` for any caller that never came through there, held on optional `LeagueStore.titlePlayoffs` only until the offseason copies it to `SeasonHistoryEntry.titlePlayoffs`, box scores never stored, every tie on its own `hashInts(lid, season, compId, round, tie, TITLE_PLAYOFF_STREAM 0x7171)` stream. **Zero shared-rng draws**, so no league scoreline moves.
- **The board credits the title the club actually won** (`ReviewInput.titlePlayoffs`), but still judges the finish against expectations — topping the table and losing the playoff is a good season with no title.
- Pool is the competition's own clubs (every entrant comes from it), season form applied, injuries honoured, suspensions not carried in. A league too short to seat eight holds none.
- UI: `/title-playoffs` (country + season dropdowns, bracket), and Standings marks the playoff winner as champion during the offseason window.

**Conferences and zones: MLS and Argentina at their real 30 clubs** (`ConferenceFormat`, `COUNTRY_CONFERENCES`, `core/conferences.ts`, `conferenceSchedule` in `core/schedule.ts`, 2026-09-13, user ask)
- **A top flight can be split in two halves that each play their own schedule**, and that is what lets a division past `MAX_DIVISION_TEAMS` fit the 38-matchday calendar: a double round robin of 30 needs 58 matchdays, two halves of 15 need 30. US: own conference twice (28) + a cross-conference rival home and away (2) + `crossRounds` 4 more = **34**. Argentina: own zone twice + the inter-zone derby home and away = **30**. Resolve through `competitionConferences` (top flights only).
- **The rival costs nothing and falls out of the circle method.** An odd half (15) leaves one club over each round; both halves are built from the identical positional `generateSchedule`, so the leftover club sits at the SAME index in both and pairing them gives every club a fixed home-and-away rival across the divide. Extra cross rounds rotate the offset from 1 so they never repeat the rival, and are spread evenly through the season. `conferences.test.ts` pins games per club, 17/17 (15/15) home split, exactly one double cross meeting and four single ones.
- **Only the schedule and the title playoff read the split.** The division stays ONE competition with ONE table: prize money, continental places, relegation, hype and the board all read the overall standings, which is what MLS's Supporters' Shield and Argentina's annual table are. So nothing downstream needed a conference concept.
- **Membership is sticky but never required.** `StoredTeam.conference` (optional, no migration — `migrate.ts` spreads `...t`) is written by `assignConferences` at world creation and after the offseason's promotion swaps; `conferenceMembers` keeps stored values while a half has room and fills everyone else into the shorter half in tid order. So a promoted Argentine club takes the zone a relegated one left, a relegated club drops the field, and a hand-built fixture with no values still resolves to two equal halves. **The US block in `CLUBS` is ordered by geography** — its first fifteen are the Eastern Conference — because tid order is what seeds a club with no stored half. Keep additions on the right side of that line.
- **Two title formats ride on it** (`TitlePlayoffFormat`): `conference` (MLS: top 9 per conference; 8v9 wild card straight to pens; best-of-three round one, games 1 and 3 at the better seed, every level game straight to pens, stored on `CupTie.series` with `homeGoals`/`awayGoals` meaning GAMES WON; one-off conference semis and finals with ET; a final hosted by the better OVERALL record) and `zones` (Argentina: top 8 per zone, `ZONE_ROUND_OF_16_PAIRS` over the zones interleaved A1,B1,A2… so every tie is cross-zone and the zone winners sit in opposite halves; straight to pens until a neutral final with ET). Straight-to-pens is `resolveCupTie`'s new trailing `extraTime` (default true, so every cup is bit-identical). A split format on an unsplit league plays `single`. `titlePlayoffRoundNames` names rounds per format; the page reads it rather than fixed QF/SF/final constants.
- **A 30-club top flight broke the domestic cup, silently.** Argentina's pyramid is 86 clubs and the US's 76, past the 64 a six-round cup seats, and `buildDomesticCup` returns **null** there — no cup at all. `DOMESTIC_CUP_MATCHDAYS` gained matchday **1**, PREPENDED: a cup takes the last `totalRounds` entries, so every country that already fitted in six rounds is byte-identical and only a seven-round cup reaches it. `DOMESTIC_CUP_PRIZE_BY_ROUNDS_FROM_FINAL` gained a seventh entry for the same reason.
- **Fixed on the way: the offseason built next season's fixtures UNSPREAD, on `origin/main` too.** Step 7 called the raw `generateSchedule` while world creation went through `buildCompetitionSchedule`, so from season 2 every division smaller than 20 played its rounds on matchdays 1..2(n-1) and sat out the rest — the opposite of the "a smaller division SPREADS across the grid" behaviour this file documents, which only season 1 ever had. Both now go through the one builder in `schedule.ts` (re-exported from `leagueState.ts`), which also throws if a season ever has more rounds than matchdays instead of silently doubling clubs up on one. **This changes every dynasty with a sub-20 division from season 2 on**, which is most of Europe, so dynasty baselines move.
- **Season length is `competitionSeasonGames`, never `2(n-1)`.** A split division plays 34 or 30, and anything that prices a season by its length reads the helper; transfer-bonus pricing (`clauses.ts` `leagueGames`) used the double-round-robin formula and read a 30-club split league as 58 games, so an appearance target looked far easier to reach than it is. `conferences.test.ts` pins the helper to the schedule `conferenceSchedule` actually builds. Grep for `competitionTeamCount(` beside a `- 1)` before trusting any other season-length arithmetic.
- **A 30-club split top flight LOSES GROUND over a dynasty, and the cause was investigated rather than tuned away (2026-09-13).** The 20-season 4-seed audit failed United States->Greece on the mean (-2.05, negative on all four seeds) against **-0.64 for a control with both top flights back at 20 clubs in one table** on the same code, so it is the split, not the rest of the change. Findings, each from a controlled probe (`scripts/conferenceSizeProbe.ts`: equal-strength twin countries differing only in shape, 4 seeds; `scripts/worldShapeAttribution.ts`: the real world, 30-club vs 20-club arms, 3 seeds):
  - **It is weaker FOOTBALL, not a quirk of the audit's all-roster mean.** Each club's best XI gains 1.7-2.2 points less over 15 seasons in a 30-club split league than in a 20-club table. Best-XI drift rises everywhere (+5 to +9) while the all-roster mean falls, so that mean is a poor strength read in general.
  - **Ruled out:** PLAYING TIME (split leagues put fewer players past the minutes nudge's 30-appearance line, but offseason development is identical in every shape), the SPLIT SCHEDULE itself (a 20-club league in two halves of 10 holds its own, +0.19 on four seeds), MONEY per club at season end, and in-season rating changes (exactly 0.00).
  - **Where it happens: the SEASON, not the offseason, and entirely through the winter window's LOANS.** Start-to-end-of-season mean runs ~0 for a 20-club table and -0.1 to -0.2 a season for a split one. Decomposed exactly by move type, paid moves cost every shape the same; loans add +0.1 to +0.24 a season to a 20-club table and ~0 to a split one, because it takes in more loans than it sends out.
  - **About HALF is the second-division ratio.** A 30-club top flight has 2 second-division clubs for every 3 of its own; a 20-club top flight over a 14-club second division reproduces both the lost loan boost and about half the best-XI deficit (-0.97 against the split's -2.01 on four seeds). **The other half is the 30-club count itself**, mechanism unproven: switching continental competitions off (so their flat prize money is not shared among more clubs) shrank it on one seed and not the other.
  - **A HEAD START DOES NOT FIX IT, measured.** Argentina 9->7.5 and the US 12->10.5 (money 0.55->0.62, 0.40->0.47) made the ladder WORSE: three rungs failed the mean gate instead of one (Argentina->Netherlands -1.15, United States->Belgium -1.57, Turkey->Greece -2.70). The leagues close only 0-3% of their gap to the big four over 20 seasons against 15-40% for their neighbours, so it is a RATE problem that a starting offset merely postpones, and moving the US up on money left Turkey the poorest league in its band. Solvency was unchanged (two single-club dips of -£1.8M).
  - **Splitting the SECOND divisions too is what shipped, and it narrows the failure without clearing it.** Argentina's Primera Nacional went to 36 in two zones of 18 and the US second division to 30 in two conferences, which restores about one second-division club per top-flight club (the half the probe attributed to the ratio), with no head start. Pooled United States->Greece **-2.05 -> -1.32**, still negative on all four seeds; Argentina, which the head start had broken, is healthy (Netherlands->Argentina +2.28, Argentina->Portugal +1.13); solvency one single-club dip. What is left looks like the other half, the 30-club count: on seeds 1-2 the US closes 12-14% of its gap to the big four over 20 seasons against Greece's 21-29%.
  - Probe traps worth keeping: `simThrough` pauses before the user's cup final and `simOffseason` silently no-ops on any other phase, so a probe must resume the season (both probes now do, and `divisionSizeProbe.ts` was fixed too); build probe worlds as a SPECTATOR, because the unmanaged user club rots and drags its own league (it cost one probe a whole twin's worth of signal); and a world under 12 continental places builds no cup at all.
- **Standings** shows each half as its own table (a dashed rule under the playoff line) with an Overall toggle — for the current season only, since no record of past halves is kept and Argentina's change yearly.
- **A SPLIT DIVISION'S HALVES MUST BE EQUAL, and an odd one silently loses its whole cross-conference schedule (2026-09-22, user report "right now it's a 24 game schedule in the east and 22 in the west").** US D2 shipped at 25 clubs, so `conferenceMembers` gave it halves of 13 and 12, and `buildCompetitionSchedule` routes unequal halves to `unequalConferenceSchedule` — which plays each half twice and **nothing across the divide, whatever `crossRounds` says**. So the division's `crossRounds: 0` looked like a deliberate setting and was really the only honest value available, the two conferences never met all season, and the East played 24 games against the West's 22. Now 24 clubs, 12 a side, `crossRounds: 8`: **22 in-conference + 8 across = 30 for everyone**, 15 home games each, every in-conference ordered pair exactly once.
  - **Uniform game counts are arithmetically IMPOSSIBLE at an odd split, so this could not be fixed by adding cross rounds — the size had to change.** Every cross game consumes one club from each half, so both halves must play the same TOTAL of them. At 13/12 with a full in-conference double round robin, 30 apiece needs each Eastern club on 6 cross games (13 x 6 = 78 fixtures) and each Western on 8 (12 x 8 = 96) at the same time. Setting the two totals equal gives `24 + C/13 = 22 + C/12`, i.e. **C = 312** — 48 cross games per Eastern club, which is not a football season. The general rule: **an odd split can only ever be two independent half-seasons of different lengths.**
  - **12/12 is the first shipped split with EVEN halves AND cross rounds, so it is a code path nothing had run.** MLS and Argentina's top flights are 15/15 (odd, so the leftover club in each half pairs off into a home-and-away rival) and Argentina's second division is 18/18 with `crossRounds: 0`. Even halves have no leftover club, hence no rival and no doubled cross fixture: all 8 are one-offs, and `conferenceSchedule`'s `firstOffset` is 0 rather than 1. `conferences.test.ts` covers it directly.
  - **The 8 are a different slice per club and that falls out of the rotating offset**, not from an rng draw: Eastern club `i` meets Western clubs `i+k mod 12` for `k` in 0..7, so each club misses a different four. Deterministic, so nothing here touches stream order. **They do NOT rotate season to season** — `buildCompetitionSchedule` takes no season and no rng, so a club's cross opponents are the same every year for the life of the save. True of MLS D1 too, and untaken.
  - **An EXISTING save is unaffected and that is not luck.** `Competition.teamCount` is fixed at creation, so an old save keeps 25 clubs and 13/12 halves, and the unequal path ignores `crossRounds` entirely — so picking up the new `COUNTRY_CONFERENCES` value from the country table changes nothing there. `competitionSeasonGames` agrees (its odd branch returns the larger half's count and never reads `crossRounds`), so the season length it reports cannot drift from the fixtures built.
  - **World 884 -> 883 clubs**, and the club dropped is the 13th ENTRY of the US D2 block rather than its last: `conferenceMembers` seats a block's first half by tid, so cutting the tail would have pushed the 13th Eastern club into the Western Conference. Memphis Keelboats goes, being the westernmost of the Eastern 13. Pinned counts live in `clubs.test.ts`, `generate.test.ts`, `leagueState.test.ts` (including the world's **15036** total fixtures, up 72: the old halves made 156 + 132 = 288 games, the new make 264 + 96 = 360), `worldIntegration.test.ts`, `competitions.test.ts`'s tid ranges, both world-setup render tests, `seo.ts` and the Manual.
  - **No dynasty audit.** The division is CLOSED (`promotionSpots: 0`) and its country is the bottom of the ladder, so this moves no promotion, no continental place and no rung; what it does move is one league's fixture count, which reaches the world only through that league's own results. Worth knowing if the same fix is ever applied to a division with promotion, where changing a season's length changes how much football a club plays before the ladder reads it.
- **World setup can build every one of these shapes on any league (2026-09-18, user ask).** `LeagueSpec` gained `d1Conferences`/`d2Conferences`/`d3Conferences` (`ConferenceFormat | null`, written onto `Competition.conferences` by `buildCompetitions`), and the panel sizes each division on its own, splits any division into two named halves with a chosen number of cross-over games, labels each link's None (from #381's per-link `PromotionLinkControls`) "None, closed divisions", a **Champion** picker for `titlePlayoff` and a **Continent** picker for `region`. Four things to know. **(a) `null` is an explicit single table**, so `competitionConferences` reads `comp.conferences !== undefined ? … : COUNTRY_CONFERENCES` — `??` would let a user's "one table" fall through to the shipped US/Argentine split. **(b) Size limits are DERIVED from the calendar**: `maxDivisionTeams(split)` is 20 for a table and 40 split (halves of 20 play 38 rounds), and every size below it fits too, odd ones included (byes in a table, unequal halves with no cross games when split, the shape #381 gave the US second division), `maxCrossRounds(n)` is what fits the rest of the 38 matchdays. `buildCompetitionSchedule` THROWS past 38 rounds, so these are correctness bounds, not taste. **(c) `normalizeLeagueSpec` runs on every World setup edit** and pulls a spec back inside them (un-splitting a 30-club division drops it to 20; cross rounds clamp; a per-half title playoff on halves too small for `CONFERENCE_PLAYOFF_TEAMS`/`ZONE_PLAYOFF_TEAMS` steps down to `single`, since the builder would otherwise skip it silently). It returns an untouched shipped spec unchanged, so `buildCompetitions(worldLeagueSpecs())` stays byte-identical (pinned). **(d) `ResolvedLeagueSpec.conferences`/`titlePlayoff` are read off `buildCompetitions([spec])` through the engine accessors**, so the editor shows what the season will actually do. Pure world-creation config, no rng draw, no migration. `test/core/customLeagueShapes.test.ts` sims a season and offseason of a player-built 36/40/20 closed conference league.

**Super cups** (`core/superCup/`, "champions cups" to the player, 2026-08-31) — one match per country plus one worldwide, played in the **preseason**
- **The whole competition is one `resolveCupTie` call per tie.** A domestic super cup is its country's league champion against its domestic cup winner; the continental one is the Continental Cup winner against the Shield winner. Single match, **neutral venue** (`resolveCupTie` already took the flag for the promotion playoff's final), extra time then penalties. `LeagueStore.superCups` holds this preseason's; `SeasonHistoryEntry.superCups` archives them at the next rollover. Both new, both migrated to `[]`/absent, and **never backfilled** — a season that opened before the competition existed played none, so absent is the truth rather than a gap.
- **Seeded at the offseason roll, played at the start of the next season, and that split is the point.** `buildSuperCups` runs beside `buildCupState` because that is the last moment all four winners are readable at once (the cups carrying them are archived a few lines later); `playSuperCups` runs in the new season, so the match is contested by the squads that will actually start it — which is what a real Super Cup does. Consequence worth knowing: **the summer window is open either side of it**, so a user who signs someone first fields him. Eager and lazy play are the same *match* (the seed is `hashInts(lid, season, compId, SUPER_CUP_STREAM)`, not a function of when it is played) but not necessarily the same *personnel*, so nothing downstream may assume a super cup was played on any particular squad.
- **The preseason gate is DERIVED (`superCupsPending`), not a third `phase` value** — nothing to migrate, and nothing to read in the ~dozen places that switch on `phase`, for a state that lasts one click. **And it is not actually a gate:** `simThrough` plays anything still pending on its way into the season rather than refusing to run. That is deliberate and it is the bug this nearly shipped with — a hard block stalls every caller that never sees the UI (autopilot's `jumpSeasons`, the headless audits, the test harnesses) with no way to clear itself. Same eager-or-lazy arrangement `playPromotionPlayoffs` uses, for the same reason. **A spectator save is the clearest case**: `SpectatorDashboard` renders none of this (there is no club to prepare) and sims straight through `simAction`, so a real gate would have deadlocked those saves at the start of every season with no button anywhere to clear it.
- **The double rule: league champion vs cup winner, and the LEAGUE RUNNER-UP steps in when one club won both** (user call). What the Community Shield does, it always produces a match, and the opponent is a genuinely strong side. The other real convention — the beaten cup finalist — was passed over because a **tier-2 club can reach a domestic cup final here**, which would put a second-division side in the showpiece far more often than reads right. The continental one needs no such rule: the two fields are disjoint by construction (see `cup/qualification`), so the same club can never hold both.
- **A two-club normalization pool would be degenerate, and this is the `cupMatchData` lesson again.** Composites z-normalize within their pool, so measuring the two contestants against each other alone makes every match read as even however far apart the sides are. A domestic super cup therefore pools its **country's clubs across every one of its divisions** — it has to, since the domestic cup is open to all of them and its winner can be a second- or third-tier club — and the continental one pools **every tier-1 club in the world**, the only baseline that means anything between two elite clubs from different countries. The pool is keyed off `country`, never an enumerated pair of tiers, which is why the third division added on 2026-09-01 needed no change here.
- **No prize money, and that is what makes it provably safe to ship.** Same call the domestic cups shipped under and for the same measured reason (real payouts there put 2 of 4 audit seeds into deficit while every strength check stayed green). With no credit, no box score kept, no injury or card carried out of the match and a dedicated rng stream, a season played with super cups is **bit-identical** to one played without — asserted directly by `superCup.test.ts` ("does not move a single league result"), which also checks the match really was played so it cannot pass by doing nothing. **That test is the gate for any future change here**: a prize credit would shift every downstream AI market decision and nothing else in the suite would notice.
- **Filed under the season it OPENS, which is the one place it differs from every other record on a `SeasonHistoryEntry`** — everything else there describes the football that closed the season. Same for the News Feed, where a super cup is the one trophy sorted at `PRESEASON_ORDER` rather than season-end, beside the summer window rather than below the champions.
- `ClubHistory.superCupTitles` reads the super-cup records directly rather than a `ClubSeasonRecord`, because a super cup belongs to no season's *table*; **a season can legitimately appear twice** there (a club that is both league champion and Continental Cup holder contests both), so it is a list rather than a set and deduplicating would undercount the cabinet. Deliberately **not** wired into the Ballon d'Or, the GOAT boards or the treble — the treble is league + Continental Cup + domestic cup and a fourth trophy would be the wrong shape, and the world-awards balance is delicate enough that adding an unmeasured term is the move those comments warn against. `COUNTRY_CUP_ADJECTIVE` gained the four countries added on 2026-08-28 (Dutch/Greek/Scottish/Serbian), which also fixes the domestic cups reading "Netherlands Cup".
- UI: `/champions-cups` (season dropdown, a card per tie), a Dashboard preseason panel offering the match ahead of the sim buttons, and a trophy row on Club History shown only once a club has one.
